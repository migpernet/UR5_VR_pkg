Guia de simulação para o Gazebo:

1 - Lançar a simulação no unity: 
Nome do projeto --> UR5_JointControl_VR_V4    

2 - Lançar o servidor via terminal
roslaunch ros_tcp_endpoint endpoint.launch

3 - Lançar o gazebo / RViz via terminal
roslaunch UR5_VR_pkg spawn_ur5_gripper_140_cam.launch      (Com Rviz)
     ou     
roslaunch UR5_VR_pkg spawn_ur5_gripper_140_cam_gazebo.launch      (Sem Rviz)

4 - Inserir objetos no gazebo
rosrun ggcnn_pkg spawn_objects.py       ou        rosrun trajectory_pkg spawn_objects_model.py (blocos coloridos)
rosrun ggcnn_pkg spawn_objects_news.py

5 - Rodar o script do GGCNN
rosrun UR5_VR_pkg run_ggcnn_teleoperation_140.py

6 - Rodar o nó responsável por ajustar o RGB para BGR
rosrun UR5_VR_pkg fix_colors_ggcnn_140.py

7 - Lançar o nó no lado do ROS para receber a pose do "GhostCube" enviadas pelo Unity e resolver a cinemática inversa com o KDL/DLS
rosrun UR5_VR_pkg kdl_teleop_solver_DLS_140.py

rosrun UR5_VR_pkg trac_ik_teleop_solver_140.py

rosrun UR5_VR_pkg trac_ik_teleop_solver_140_workspace_calibration.py

8 - Rode o planejador de trajetórias (Polinômio quíntuplo)
rosrun UR5_VR_pkg quintic_planner_node_140.py

9 - Rode o nó responsável pelo comando das juntas do robô
rosrun UR5_VR_pkg robot_commander_node_140.py

10 - Para fazer o teste de Latência
rosrun UR5_VR_pkg latency_echo_140.py

11 - Conectar a webCam no computador Ubuntu

12 - Lançar o nó no lado do ROS para transmitir informações da webCam externa
rosrun usb_cam usb_cam_node _video_device:="/dev/video0" _pixel_format:=yuyv 

13 - Iniciar a simulação no unity apertando o "play"

14 - Verificar a criação dos tópicos e publicações com "rostopic"

15 - Abrir o "rqt_graph" via terminal para visualizar os nós e tópicos publisher e subscriber.

Nota de hardware: Lembra quando o Action Server "engasgou" e nós trocamos para um Publicador contínuo? Se tivéssemos mantido o Action Server, você estaria tentando assinar 90 contratos por segundo com o robô. A rede teria colapsado!


Abordagem Híbrida com o Controller Manager

* Para o Menu/Autônomo (Planejador Quíntuplo): Usar o Action Server. Ele garante um movimento longo suave, obedece aos 3 segundos exatos e monitora os limites de torque do braço.

* Para o VR/Teleoperação: Usar o Publisher Contínuo (Streaming). Ele entrega a fluidez de latência zero que o rastreamento da mão exige.



***********

A limitação de velocidade/aceleleração que realmente protege o movimento precisa existir também no quintic planner ou, idealmente, no nível final do controlador.

Isso é especialmente importante quando você passar de Gazebo para o UR5 físico.
